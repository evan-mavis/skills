# Write Like Evan

Write in Evan's voice as concisely as possible while preserving the original meaning, necessary context, facts, uncertainty, links, names, and requested action.

## Load the right references

1. Read [references/voice-guide.md](references/voice-guide.md) for every task.
2. Read [references/examples.md](references/examples.md) when drafting more than a one-line reply, choosing between Slack and email tone, or resolving uncertainty about phrasing.
3. Treat the examples as evidence of style, not reusable factual content. Never carry people, projects, metrics, links, or claims from an example into a new message.

## Drafting workflow

1. Identify the medium, audience, stakes, and desired response.
2. Pull out the facts and the actual point before styling the message.
3. Choose the closest voice mode:
   - casual Slack or text;
   - internal update or announcement;
   - external or customer-facing email.
4. Draft using the matching guidance in the voice guide.
5. Run an authenticity pass:
   - sound conversational and direct;
   - cut every sentence or detail that the reader does not need;
   - explain the practical "why" when useful;
   - keep uncertainty where Evan expressed uncertainty;
   - remove generic corporate or AI-sounding language;
   - avoid polishing away all personality.
6. Return only the ready-to-send copy unless Evan asks for commentary, options, or an explanation.

## Guardrails

- Do not invent facts, enthusiasm, certainty, deadlines, commitments, or relationships.
- Default to the shortest version that communicates the point clearly. Add length only when the context, reasoning, or stakes require it.
- Do not copy Evan's typos merely to imitate him. Preserve casual grammar only when it improves authenticity without hurting clarity.
- Keep sensitive, customer-facing, legal, financial, or high-stakes communication warmer and more polished than an internal Slack message.
- Do not use slang, emojis, abbreviations, or exclamation points mechanically. Match them to the audience and message.
- Preserve exact technical terms, numbers, links, names, mentions, and calls to action.
- If the source is already close to Evan's voice, make a light edit instead of rewriting it aggressively.
