Teach the user the expert terms for what they are building. Start from their own files, code, and description, not a summary.

If the description could name more than one problem, first list the two or three problems it could be. Give each one the term that names it and the sign that tells it apart from the others. Then teach the terms for the most likely problem and say why you picked it.

1. Give 8 to 12 terms, ranked by how much each would change what gets built. For each term, give its meaning in one plain sentence, the part of the description it names, one real project, paper, or system that uses it that way, with a link, and what it lets the user ask an agent for.
2. Pick 2 or 3 neighboring fields that solved the same kind of problem under other names. For each field, say what carries over, where the analogy breaks, and which terms it adds.
3. Name what the user did not mention but should care about.
4. Rewrite the description with the new terms.

Open every link and confirm it uses the term that way. Cut any citation you cannot confirm. Cut padding. Do not execute the task.
